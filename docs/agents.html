Agent playbook

Reels is designed around one asymmetry: the agent owns content, the repo owns craft. AGENTS.md is the contract that keeps those safe from each other.

The contract, in one line

Only docs/scenes.json may change. The schema, the design system, the player, the workflow — none of it is the agent’s job.

What AGENTS.md tells the agent

  • Output valid JSON against scenes.schema.json — enforced locally with npm run validate and again in CI.
  • 6–12 scenes, intro → conclusion, ending on an outro.
  • Duration 4–10s per scene; headings ≤ 6 words; body ≤ 15 words.
  • Unsplash-only images with mandated query params; real URLs, never invented IDs.
  • narration written for every scene even though renders are silent today — it’s the TTS hook.
  • Commit message content: <video title>, push, stop. Do not trigger the render.

Proven prompt

Read AGENTS.md, then scenes.schema.json, then DESIGN.md.
Take the content below and generate docs/scenes.json.
Rules: title first, outro last, 6-12 scenes, all six types allowed,
validate with npm run validate before committing.

CONTENT:
<paste article / notes / topic here>

The review loop

  1. Agent writes docs/scenes.json, runs npm run validate, commits, pushes.
  2. You watch the Pages preview at /player.html. Does it read well? Do images load?
  3. Ask for scene-level fixes: “scene 3 heading is vague”, “swap the farm photo”, “drop scene 5”.
  4. Happy? Actions → Render video → Run workflow. Download the artifact.

Why the CI gate exists

Agents are great at content and occasionally creative with JSON — invented photo IDs, 14-word headings, duration 30. The workflow runs npm run validate before touching Chromium, so a malformed deck fails in seconds instead of producing a broken 90-second recording. The schema is the bouncer; the agent never gets to the video.

Antigravity (agy) notes

Antigravity reads AGENTS.md the same way other coding agents do. Point it at the repo, give it the proven prompt, and let it work the loop. Two practical tips:

  • Paste the schema or link it — agents that see the enum list stop inventing scene types.
  • Ask for the commit message content: … explicitly so git log stays readable over time.

Extending the system

Want a new scene type (e.g. comparison for A/B)? That’s a human change: add it to TEMPLATES in docs/player.js, add the CSS, extend scenes.schema.json, and document it in DESIGN.md and this page. The agent gains a new ability exactly when you ship it — never before.
